# План исправления багов (Bug Fix Plan)

Данный документ описывает план устранения 37 выявленных багов (4 Critical, 9 High, 14 Medium, 10 Low) в кодовой базе проекта. Задачи распределены по приоритетам для поэтапного выполнения.

## 🔴 CRITICAL (Критические уязвимости) - Выполнить немедленно

### 1. Брутфорс кода верификации email (auth.ts:278-334)
- **Проблема:** Отсутствие ограничения попыток (rate limiting) функции `verifyEmailAction`. Злоумышленник может подобрать 6-значный код за 15 минут.
- **План исправления:** 
  1. Добавить счетчик неудачных попыток (в БД или Redis) привязанный к email.
  2. Внедрить блокировку при превышении лимита (например, 5 попыток) с аннулированием текущего кода.

### 2. Брутфорс кода сброса пароля (auth.ts:392-455)
- **Проблема:** Отсутствует лимит попыток для функции `resetPasswordAction`. Неудачные вводы не инвалидируют код.
- **План исправления:**
  1. Реализовать отслеживание неудачных попыток ввода.
  2. При достижении лимита помечать код как недействительный и требовать повторный запрос на сброс.

### 3. Состояние гонки (Race condition) в кэше реестра (document-registry.ts:37-79)
- **Проблема:** Параллельные запросы вызывают множественные `refreshCache()`, перезаписывая данные после `invalidateRegistryCache()`.
- **План исправления:**
  1. Добавить мьютекс или блокировку (lock) на операцию обновления кэша.
  2. Использовать флаг `isRefreshing` для предотвращения одновременных запросов к БД.

### 4. Некорректная инициализация отправки писем (email.ts:12-20)
- **Проблема:** Транспортер Nodemailer создается при загрузке. Без `SMTP_USER`/`SMTP_PASS` на старте он остается сломанным навсегда, письма не отправляются.
- **План исправления:**
  1. Перенести создание транспортера внутрь функции или использовать паттерн Singleton с ленивой инициализацией (Lazy Initialization).
  2. Добавить проверку конфигурации перед отправкой.

## 🟠 HIGH (Высокий приоритет) - Исправить в текущем спринте

### 5. Доступ заблокированных пользователей (middleware.ts:207, security.ts:33-55)
- **Проблема:** Middleware не проверяет актуальный статус блокировки, только JWT токен.
- **План исправления:**
  1. Добавить запрос к БД или проверку в сессии (Redis) статуса `isBlocked` при валидации токена.

### 6. Пересечение времени действия кодов (auth.ts:371-377)
- **Проблема:** Столбец `code_expires_at` используется для верификации и для сброса пароля одновременно.
- **План исправления:** Разделить колонки на `email_verify_expires_at` и `password_reset_expires_at` (или добавить тип токена).

### 7. Локальный Rate Limiter в Serverless (auth.ts:29-53)
- **Проблема:** `loginAttempts` в виде Map в памяти каждого инстанса не работает в масштабируемых средах (Vercel).
- **План исправления:** Перенести Rate Limiting в Redis (Upstash) или Postgres.

### 8. Ошибка деления на ноль (permit-detail-view.tsx:82)
- **Проблема:** Краш `Infinity/NaN` при `numberOfFloors === 0`.
- **План исправления:** Добавить тернарный оператор или математическую проверку перед вычислением.

### 9. Устаревший CSRF токен (file-upload-zone.tsx:37-56)
- **Проблема:** `csrfToken` не обновляется в замыкании `handleUpload`, первая загрузка всегда падает.
- **План исправления:** Добавить `csrfToken` в массив зависимостей `useCallback` или использовать `useRef`.

### 10. Краш приложения из-за Gemini ключа (gemini.ts:11-15)
- **Проблема:** Отсутствие ключа вызывает глобальный `throw`, обрушая даже страницы авторизации.
- **План исправления:** Вынести проверку `GEMINI_API_KEY` внутрь экспортируемых функций, которые ее используют.

### 11. Отсутствие default return (notifications.ts:86-113)
- **Проблема:** `getNotificationContent` возвращает `undefined` для новых типов, вызывая падение приложения.
- **План исправления:** Добавить безопасный `default` case с возвратом заглушки или пробросом обрабатываемой исключительной ситуации.

### 12. Состояние гонки в кэше профилей (document-selector.ts:19-64)
- **Проблема:** Аналогично п.3 для поисковых профилей.
- **План исправления:** Реализовать блокировку обновлений (mutex/lock) при инвалидации.

### 13. Брутфорс смены пароля (profile.ts:141-195)
- **Проблема:** Отсутствует Rate Limiting на ввод 6-значного кода при смене пароля из профиля.
- **План исправления:** Внедрить ограничение попыток в БД, аналогично п.1 и п.2.
