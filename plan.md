# План Разработки (для Claude Code)

Этот документ описывает шаги по добавлению функционала регистрации, работы с email и профилями для обычных пользователей и администраторов. Проект использует Next.js, Supabase (как базу данных) и собственную систему аутентификации на основе JWT, `bcryptjs` и `jose`. Рассылка писем должна осуществляться через библиотеку `resend`, которая уже есть в `package.json`.

## 1. Обновление Базы Данных (Supabase Migrations)
Необходимо создать новую миграцию в папке `supabase/migrations/` для добавления новых колонок в таблицу `users`:
- `email` (TEXT, UNIQUE, NULL)
- `email_verified` (BOOLEAN, DEFAULT FALSE)
- `verification_code` (TEXT) - для подтверждения почты при регистрации
- `reset_code` (TEXT) - для сброса пароля или изменения пароля
- `code_expires_at` (TIMESTAMPTZ) - время истечения срока действия кода

*Примечание: Поскольку администраторы создаются через сидирование/миграции или напрямую из админ панели, поле `email` не должно быть обязательным на уровне БД.*

## 2. Регистрация и Подтверждение Почты
- **Схемы валидации (`lib/validations.ts`)**: Добавить схему `registerSchema` с полями `username`, `email` и `password`.
- **Серверные экшены (`actions/auth.ts`)**:
  - Создать экшен `registerAction(data)`: добавляет пользователя в БД со статусом `email_verified: false`, генерирует 6-значный `verification_code` и отправляет код на указанный email с помощью `resend`.
  - Создать экшен `verifyEmailAction(email, code)`: проверяет совпадение кода (и expiration). Если всё ок, ставит `email_verified = true`.
- **UI Страницы**: Создать страницы `/register` и `/verify-email`. Страница `/register` должна быть сделана в едином стиле со страницей `/login`.

## 3. Функция "Забыли пароль"
- **Серверные экшены**:
  - `forgotPasswordAction(email)`: находит пользователя по `email`, генерирует 6-значный `reset_code` (либо токен), сохраняет в БД с тайм-аутом, отправляет на почту.
  - `resetPasswordAction(email, code, newPassword)`: проверяет код, если совпадает, хеширует новый пароль через `bcrypt` и обновляет поле `password_hash` в таблице `users`.
- **UI Страницы**: добавить страницы `/forgot-password` и `/reset-password` (или сделать в виде нескольких шагов на одной странице).

## 4. Панель Администратора (Создание юзера и Профиль)
- **Создание юзера в админке**: Убедиться, что форма создания нового пользователя в админке (`actions/admin.ts` -> `adminCreateUser`) **НЕ ТРЕБУЕТ** наличие почты. Текущий функционал должен работать без изменений.
- **Профиль Администратора**:
  - В шапке админ-панели (`app/admin/page.tsx`), рядом со стандартными кнопками (ThemeToggle, Refresh, Logout) — "как обычно" — добавить иконку Профиля администратора.
  - При нажатии открывается страница или модальное окно профиля администратора (например, `/admin/profile` или диалог).
  - В профиле администратор может просто сменить свой пароль (ввести текущий пароль и новый). Никакой почты и кодов подтверждения для админа не требуется (так как админ изначально создается с дефолтным паролем при миграции).

## 5. Профиль Пользователя и Боковое Меню
- **Боковое меню (`components/dashboard/sidebar.tsx`)**:
  - Удалить статичный текст `"Building Codes"` и `"Powered by Gemini AI"`.
  - В левом нижнем углу вместо этого текста добавить иконку профиля (имя пользователя/аватар), которая выглядит как кнопка.
- **Страница профиля (`app/profile/page.tsx`)**:
  - При клике на иконку в сайдбаре пользователя перенаправляет на `/profile`.
  - На странице профиля можно изменить:
    - `full_name`
    - `username`
  - Функция "Сменить пароль" (Работает в 2 шага):
    - 1. Пользователь нажимает "Отправить код для смены пароля". Бэкенд генерирует код и отправляет на `email` юзера.
    - 2. Пользователь вводит полученный код с почты и новый пароль. Бэкенд проверяет код и меняет пароль. Изменение пароля без кода подтверждения с почты для обычного юзера недоступно.

## 6. Требования к реализации
- Использовать `resend` для отправки писем (он уже есть в `package.json`). Понадобится добавить в систему переменные `.env` для API-ключа Resend.
- Использовать существующие UI компоненты из папки `components/ui/` (Tailwind, Radix).
- Все новые компоненты и страницы должны поддерживать светлую/тёмную темы.
- Все обращения к БД должны проходить через паттерн `createAdminClient` в серверных экшенах.
